# Token Tracker V3

Token Tracker V3 is the follow-up client/data contract for the original V2 repository. It keeps the V2 scripts and routes available while adding a seven-widget Scriptable set.

## Widgets

- `TokenOverviewV3.js` — all-time total, today, projection, Top 1 / Top 2 and seven-day rhythm.
- `ModelRankingV3.js` — model ranking by period and source.
- `ModelFocusV3.js` — detail for one ranked model.
- `UsageRhythmV3.js` — seven-day real token bars, average, peak and projection.
- `ActivityCacheV3.js` — 180-day activity and streak context.
- `CacheHealthV3.js` — cache read, cache creation, basis and cache rate.
- `ResponsePulseV3.js` — request count and arithmetic mean of positive response times.

Every V3 script composes Small, Medium and Large independently. The iOS widget family is selected by Scriptable at runtime; it is not a scaled screenshot.

## Data rules

The backend and widgets use these rules consistently:

1. Main Token is `prompt_tokens + completion_tokens`.
2. Cache read and cache creation are reported separately and are not added to Main Token.
3. A standard log event contributes `request_count = 1`; aggregate request totals sum that field.
4. `avg_latency` is the arithmetic mean of positive `use_time` samples only. Zero and negative values do not become latency samples.
5. Model family mapping is deterministic; `Nano Banana` / `nano-banana` models are grouped with Gemini.
6. `source + request_id` is the idempotency boundary.

## Settings

Run `SetupTokenTrackerV3.js` once in Scriptable. It saves the entered URL and API key to `token-tracker-v3-settings.json` in Scriptable's local documents directory. V3 widgets fall back to the V2 settings filename for compatibility. Neither settings file belongs in Git.

## Parameters

The source-aware widgets accept these period values:

- `today`
- `7d`
- `month`

Examples:

```text
ModelRankingV3.js: 7d,all
ModelFocusV3.js:   1,month,all
CacheHealthV3.js:  today,all
ResponsePulseV3.js: 7d,all
```

The second value is a source ID or `all`. Source IDs come from the local, uncommitted `backend/sources.json`.

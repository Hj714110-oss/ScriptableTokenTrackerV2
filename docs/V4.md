# Token Tracker V4 · Atelier

V4 is a visual redesign of the widget family. It reads the same `/v3` payload, so V2/V3 scripts, routes and settings keep working alongside it.

## How it is built

- **One source:** `src/v4/core.js` holds the design tokens, drawing primitives and seven views, each with three sizes.
- **Generated widgets:** `tools/build_v4.py` writes seven self-contained `scriptable/*V4.js` files from it. Edit the core, then rebuild. `verify.py` fails if the generated files drift from the core.
- **Rendering:** each widget is a single full-bleed `DrawContext` image, set as the `ListWidget` background.
  - Widget sizes come from a per-screen-width table (iPhone mini → Pro Max), so the image maps 1:1 onto the home-screen slot.
  - `DrawContext` cannot measure text, so long numbers and model names shrink or truncate from width estimates.
- **Light and dark:** the palette follows `Device.isUsingDarkAppearance()` at refresh time, refreshing about every 2 minutes.
- **Settings:** read in order from `token-tracker-v4-settings.json`, then `token-tracker-v3-settings.json`, then `token-tracker-v2-settings.json`.
- **Cache:** the last good payload is kept in `token-tracker-v4-cache.json` and shown with a "缓存" status when the network fails.

## Widgets

| Script | Small | Medium | Large |
|---|---|---|---|
| TokenOverviewV4 | today, delta, 7 bars | today + 7-day bars with average and projection | ring vs projection, three tiles, 30-day area, Top 3 |
| ModelRankingV4 | Top 3 with share bars | Top 5 with bars | total, share strip, Top 5 with 7-day sparklines |
| ModelFocusV4 | name, share ring, tokens | ring + three stats | ring, tiles, 7-day bars |
| UsageRhythmV4 | 7 bars with labels | stats + bars | tiles, 7-day bars, 30-day area |
| ActivityCacheV4 | streak + 12-week calendar | stats + 26-week calendar | 26-week calendar with months and legend, tiles, 30 bars |
| CacheHealthV4 | hit-rate ring | ring + read / create / basis | ring, bars, 7-day hit-rate line, prompt vs cache |
| ResponsePulseV4 | mean latency + pulse | latency line over request bars | hero latency, tiles, request bars, latency area |

Parameters are `[rank,]period,source` in any order:
- **rank:** a number such as `1` (Model Focus only).
- **period:** `today`, `7d` or `month`.
- **source:** `all` or a source ID from `backend/sources.json`.

## Data rules (unchanged)

1. Main Token is `prompt_tokens + completion_tokens`.
2. Cache read and cache creation are separate fields and never added to Main Token.
3. Requests are the sum of `request_count`.
4. Latency is the arithmetic mean of positive `use_time` samples. There is no P95/P99.

## Previews

`tools/v4/demo_payload.py` runs synthetic, fictional events through `backend/analytics.py` and saves the payload, marked `ALL VALUES ARE FICTIONAL`.

`tools/v4/preview/render.js` loads the real V4 scripts in Chromium on top of a minimal Scriptable shim (`shim.js`). It renders all 42 layout × theme combinations at 3× scale, and `compose.py` builds the README images from them. Fonts are substituted (Inter, JetBrains Mono and Noto Sans CJK in place of SF Pro and PingFang), so on-device type differs slightly.
